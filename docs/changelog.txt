FastRoute changelog


0.6 (unreleased)

Added
  - Cut, copy and paste in a session's block list: Ctrl+X, Ctrl+C, Ctrl+V to paste below the selected block and Ctrl+Shift+V to paste above it, all four on the Block menu and the context menu too. Two paste commands rather than one with a setting, because two is already everything - above the first block is the start of the list and below the last is the end, so there is nowhere a block can go that they do not reach, and with nothing selected a paste goes on the end. The clipboard holds the block itself and not a description of it, so a plugin's parameter values, the EQ bands and the action hotkeys all come through; it is FastRoute's own rather than Windows', because a cut is destructive and what comes back has to be exactly what went in. It is process wide, so a block cut in one session window pastes into another. The one thing a paste changes is a hotkey the destination session already answers to, which is cleared with the status line saying how many - which gives a cut block its keys back and stops a copied one claiming the original's. Each command says what it did, since there is nothing on screen that would. Asked for by Gavin Grundlingh.
  - {index} in a recorder's file name template: the block's place in the pipeline, counted from one, so "{index}. {block}" writes "1. Mic.flac", "2. Screen reader.flac", "3. Game.flac" and the files sort into the order the blocks are in. Padded to the width the session needs, so a session of twelve blocks numbers them 01 to 12 and the ninth still sorts before the tenth, while a small session is not padded at all. {blocknumber} works too, being the name it was asked for by. A recorder's own mixed file is of no one block, so both come out empty there, as {block} already did. Asked for by Gavin Grundlingh.
  - A Recorder block can be set to a sample rate and a bit depth of its own, rather than always writing the session's rate at 16 bit. Both lists hold only what the chosen format can actually be written as on this machine, which is not the same for each: WAV takes any rate at 16, 24 or 32 bit float; FLAC is 16 or 24 bit from 44100 up; MP3 stops at 48000; AAC is 16 bit; Ogg Vorbis stops at 48000 and its bitrate list shortens as the rate comes down, because libvorbis refuses 192 kbps at 22050; and Opus writes 48000 whatever it is handed, so that control is switched off rather than left there doing nothing. The encoders are asked rather than tabulated. The conversion runs on the recorder's own writer thread at the resampler's best quality, so it costs the session no latency. A Buffer block's Save offers the same two settings, and a recorder writing a file per input block writes every track the same way, so they still line up. Asked for by Gavin Grundlingh.
  - A Recorder block has a recording mode: the mix in one file, as before; a file per input block above it, named after the block; or both. A per-block file is taken at the input block itself, with that block's own volume applied and nothing below the block in the list, so the tracks are not slices of the mixed file - which is the point, since a track is then still raw enough to work on. They do line up with each other: a block switched off writes silence rather than nothing, and the two settings that would cut each file in a different place - skipping silence, and splitting by megabytes - are not passed on to tracks. Splitting by minutes is. Naming the blocks names the files; two unnamed blocks of one type become "Application" and "Application 2". Asked for by Gavin Grundlingh.
  - {block} works in a recorder's file name template, and in a buffer's. It was listed in the code as though it did and never substituted.
  - A block action's hotkey - rewind, forward, back to live, save the buffer - is only registered while its session is running, so the same key can do the same thing in every session as long as one of them runs at a time, and a key used only while recording is not taken from the rest of the machine the rest of the time. Nothing is lost: an action is done to a running graph, so pressed while the session was stopped it answered with the low tone and changed nothing. A block's own on and off key is not treated this way, since switching a block off is an edit to the document and means the same either way. The hotkey window now says which of the three kinds you are setting and what it will do. Asked for by Gavin Grundlingh.
  - An application block can be told to start whether or not the programs it captures are running, with "Wait for them to start rather than refusing to run". A session that records a game is put together before the game is launched, so refusing to start was the only thing in the way: the capture already takes a program into the mix when it launches. Works for a block naming one program as well as several. The cost is that a name spelled wrongly and a program not started yet look the same to a block that is waiting, so the block that refuses is still the better one while a session is being set up. Asked for by Gavin Grundlingh.
  - An application block can name more than one program. The list is checkboxes now instead of a single choice, and each ticked program is captured with its own child processes and mixed into the one block - so a session can have a screen reader block naming every screen reader and a game block naming every game, each one level and, when recording, one track. A program named but not running joins the mix when it starts, so only none of them running is an error. Asked for by Gavin Grundlingh.
  - The blocks library remembers which groups you left shut, and opens with the first group focused rather than wherever the tree happened to leave the cursor. Asked for by Gavin Grundlingh.
  - ASIO input and output blocks. Note that the first build of these crashed on choosing a driver that actually worked; fixed before 0.6 was released. Pick the driver and which two of its channels are the left and right. An ASIO input and an ASIO output on the same interface share one callback and one clock, so nothing between them is resampled or drifts. ASIO also mixes with Windows devices in either direction, through the same buffer any two unrelated clocks need. One interface per session, because that is all ASIO allows. Buffer size and sample rate belong to the driver's own control panel, and there is a button for it.
  - FastRoute is on GitHub, at https://github.com/masonasons/FastRoute, under the GPL version 3. Every push builds there and replaces the "latest" release.
  - Updating itself. Help > Check for Updates asks now; Settings has how often to ask on its own - never, at startup, hourly or daily - and whether to install without asking. Off by default. Applying an update leaves sessions, settings and recordings alone, because the zip holds nothing but the program and its documentation.
  - The file properties finally show a version. It lives in src/version.h now and the resource, the zip name and the release label all read it from there.

Fixed
  - A Recorder block set to FLAC in a session running at 32000 Hz, or any other rate Windows' FLAC encoder does not have, refused to start and told you to change your output device. It now names the rates that encoder does have, and the block's own sample rate setting is the answer rather than the session's.
  - A WAV recording's size was worked out as 16-bit stereo whatever it was, which is what the splitting by megabytes and the size in the status line both rely on. It follows the file's own depth and rate now.
  - Opus recording resampled twice when the session was not at 48000 Hz: once into the recorder and once inside the Opus encoder. One conversion now, at better quality.
  - Nothing to fix for devices that disagree about sample rate or bit depth: they are converted at the edge of the graph and the session runs at one rate throughout, which is the first output block's own. Bit depth never reaches the mix at all - every endpoint is opened asking for float32 and Windows converts on the way through - so a 16-bit microphone and a 24-bit interface mix without being told about it. Written down now, along with the part that is worth knowing: two devices never run at exactly the same rate even when they agree on paper, and the drift is absorbed by resampling by the ratio measured between frames in and frames out rather than by the rate either device claims. Asked by Gavin Grundlingh.
  - Nothing to fix for pausing a recording: switching a Recorder block off and on again has always paused and resumed it, keeping the same file. It is written down now. Asked by Gavin Grundlingh.
  - A Recorder block set to AAC, Ogg Vorbis or Opus recorded a WAV file instead, named with the extension of the format that was asked for. The check that turns a block's settings into a recording's settings was written when WAV, FLAC and MP3 were the only three formats and allowed 0 to 2; the three added later fell outside it and fell back to WAV. The same check serves a Block Actions buffer's Save, so saving a buffer in one of those formats did the same thing.
  - The clash report for hotkeys that could not be registered was written to the error log every time the table was rebuilt. It is now written only when it changes, which matters more than it did: the table is rebuilt on every session start and stop now, not only on save.
  - A global hotkey was acted on through a reference into the table of bindings, and acting on one can rebuild that table. Nothing reached the dangling reference, but nothing was stopping it either. It is copied first.
  - An application block's list only held programs that were playing audio at the moment it was built, so a program running quietly could not be found in it and had to be typed in by hand. It now lists what is playing, then everything with a window on screen, and has a Show every running program box for anything with neither. Reported by Gavin Grundlingh, who suspected 32-bit programs were being left out; they were not - a 32-bit program with an audio session was always listed - but a quiet one was, whatever it was built as.
  - The volume slider in an application block overlapped the OK, Apply and Cancel buttons by a few pixels.
  - The pitch wandered on a poor link. Four things in the ring that buffers every capture were behind it, and they compounded: a glitch was counted once per dropped frame rather than once per overflow, so a single burst arriving after a stall counted in the hundreds and latched the drift correction on at its five-glitch threshold; the correction was then allowed five percent of pitch shift, nearly a semitone, with a gain that let one packet of buffer depth ask for one and a half percent, so it rode the depth and wandered; the drift estimate was biased upward because a read that found the ring empty was left out of it while the audio arriving just after was counted in; and there was only one buffer of headroom above the working depth, so the catch-up burst after a stall overflowed and audio was discarded frame by frame. The correction is now clamped to a quarter of one percent, about four cents, with a gain fifty times gentler; there are two buffers of headroom; and the other two are fixed outright. On a link stalling for 120 ms every two seconds: 3709 glitches and 14.85 cents of deviation before, 10 glitches and 0.00 cents after.
  - Net Receive concealed a lost packet by dropping it rather than replacing it, which made the stream shorter than the sender sent. The ring in front of the mixer reads that as the sender's clock running slow, engages its drift resampler, and resamples the whole session - which was heard as the pitch wandering about, worse the more the network lost. Gaps are now filled to exactly the length that went missing, worked out from the sender's own frame counter.
  - Net Receive threw away any packet that arrived out of order, having already concealed for it, so one reordering cost two packets instead of none. Packets are now held in a jitter buffer and played in sequence order, so a late or overtaken packet is used. A duplicate is dropped rather than played twice.
  - A missing packet was given up on the instant a gap was noticed. It is now waited for until half the buffer has passed, which is most of what "late" means on a real link.
  - The Opus encoder was asked to carry redundancy for error correction and the decoder never asked for it back, so the bitrate was spent and the benefit thrown away. The receiver now asks the packet after a gap to rebuild the one that went missing.
  - The VBAN path had the same dropped-concealment fault, by way of a cleared buffer immediately after filling it.

Added
  - Net Receive and Net Send blocks: audio over the local network, either between copies of FastRoute or to and from anything that speaks VB-Audio's VBAN protocol (VoiceMeeter, VBAN Receptor on a phone, and so on).
  - A FastRoute sender announces itself on a multicast group, so a Net Receive block lists what it has heard by name and nobody has to know an address. A VBAN host is found by being asked, which FastRoute now does, and answers, so it turns up in the same list.
  - Senders can broadcast to a group that any number of receivers can join, or serve one receiver at a time across subnets, a VPN or the internet. In that second case the receiver does the asking: start the sender, then name that machine in a Net Receive block on the other one, and the sender sends to whoever asked. Nothing has to be forwarded on the receiving side, because the asking is outbound from there.
  - PCM at 16 bit, 24 bit and 32 bit float, FLAC and Opus. A VBAN stream is 16 bit PCM, which is what VBAN carries.
  - Opus settings on a dialog of their own: how much packet loss to protect against, complexity, whether it is carrying speech or music, constant or variable bitrate, and whether to send almost nothing while the input is silent.
  - Net Receive reports what the network is doing to it - frames lost as a percentage, packets out of order, packets too late to use, and the longest a packet had to be held, which is the figure to size the buffer from.
  - Adjustable packet length, buffer depth, Opus bitrate and multicast hop limit. The hop limit applies only to a group: a packet sent to one named host keeps the system's own TTL, since one hop would not get it past the first router. Sending to a group only works on the local network - no internet provider carries multicast - so a remote machine has to be reached by sending to one host. The packet length control says what it really settled on: a packet has to fit one datagram, so 10 ms of 16 bit stereo at 48 kHz does not fit and is cut to 7.3.


0.5 (released 7 September 2026)

Added
  - Pitch Shifter block, built on Signalsmith Stretch: semitones, cents, and a quality setting that chooses how much delay to spend (120, 60 or 30 ms). At no shift it costs nothing and delays nothing. It does not preserve formants, so a voice shifted up goes up whole.


0.4 (released 30 August 2026)

Added
  - Noise Gate: lookahead, 0 to 50 ms, so the gate is already open when the sound arrives instead of still opening. Costs its own length in latency. Existing sessions load with none; new gate blocks start at 5 ms.

Changed
  - Sliders: Up and Page Up now raise the value and Down and Page Down lower it, instead of the other way round. Left, Right, Home and End are unchanged.
  - Sliders report their parameter rather than their position. A trackbar reports where its thumb is as a percentage of its range, so the parametric frequency slider read as "68" at 250 Hz and a pan hard left read as "0". Every slider is now annotated with the value written beside it, so a screen reader says "250 Hz", "hard left", "-6 dB", and a plugin's sliders say whatever the plugin calls the value.


0.3 (released 27 August 2026)

Added
  - Channel Mixer: volume and pan per channel, with a reset back to the defaults.
  - Apply button (Alt+A) on every block parameter dialog: pushes the change into the running session without closing.

Changed
  - RNNoise runs at any sample rate. The bus is converted to 48 kHz around the model and back, instead of the block refusing to start below it. Costs about 5 ms extra at 44.1 kHz; nothing changes at 48 kHz.
  - Access keys that two controls in the same dialog were sharing now differ, in the Recorder, Buffer and Settings dialogs.


0.2 (released 24 August 2026)

Added
  - Normaliser: target level, lookahead, maximum boost, release.
  - Clipping Monitor: beeps on clipping, does not alter the audio.
  - Session and block hotkeys can be global or window scoped.
  - Hotkey keys are named in a text field rather than picked from a list, so arrows, Home, End, the keypad and the media keys can all be bound.
  - Ctrl+Shift+O opens a session's recording folder.
  - A default folder in Settings for new Recorder blocks.
  - Block actions: blocks that have actions can have a hotkey per action.
  - Buffer block: keeps the last so many seconds, with rewind, fast forward, jump to live and save.

Fixed
  - Reordering blocks could terminate the process, when the move promoted a second output block to master.
  - System audio with exclusions captured applications playing to other output devices. It is now scoped to the block's own device.
